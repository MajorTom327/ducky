# ducky-app

Pure, view-agnostic state machine of ducky (depends on `ducky-core` and, for query parameters, `ducky-sql`). It owns the application state, the messages a front-end or the runtime can send, and the commands the runtime must execute. No IO, no async, no terminal code: a TUI or a Dioxus front-end renders `AppState` and turns user input into `Msg`.

```text
front-end input ──Msg──▶ update(&mut AppState, Msg) ──Vec<Command>──▶ runtime ──Msg──▶ update …
```

## Public API

- `update(state: &mut AppState, msg: Msg) -> Vec<Command>`: the only state transition. Messages addressed to a screen, tab kind or modal that is not active are ignored; responses for a request that is no longer current (`PageLoaded`, `DetailsLoaded`, `FilePreviewLoaded`, `Connected` without a pending connect) are dropped.
- `Loadable<T>` (`Idle`, `Loading`, `Ready`, `Failed`) with `ready()` and `is_loading()`.
- State: `AppState` (`new`, `workspace`), `Screen`, `ProfilePicker` (`new`, `rows`, `visible_profile_indexes`, `selected_visible_profile_index`; filter `Input` and `PickerMode` `Filter` / `Navigate`), `ProfileRow` (`Project(name)` / `Profile(index)`), `profile_rows(profiles, filter)`, `profile_kind_name`, `Workspace` (`new`, `active_tab`, `tab_index`, `query(tab_id)`, `sidebar_items`, `palette_items(query)`, `schema_names`), `Focus`, `Sidebar` (selected item, filter, `width`, `is_collapsed`), `SidebarItem` (relation, kind, estimated row count), `TabId`, `Tab` (`title`), `TabContent` (`Table`, `Query`, `Files`, `Dump`, `Restore`), `GridCursor`, `TableTab`, `TableView`, `Document`, `QueryPane`, `RunState`, `PendingSave` (tab id, name, content), `QueryView` (`new`, `selected_result`; `confirmed_profile_index` remembers the staging profile a run was confirmed on), `FilesView`, `JobKind`, `JobState`, `DumpView`, `RestoreView`, `NoticeLevel`, `Notice`, `Modal` (including `ReferencePicker`), `PromptKind`, `Prompt`, `ConfirmKind` (`OverwriteFile`, `RunScript { tab_id, sql }`, `Restore`), `Confirm`, `RowDetail`, `ParameterForm` (`values`, `selected_field`), `ParameterField` (`value`), `CommandPalette`, `PaletteItem`, `PaletteAction`.
- Constants: `PAGE_SIZE` (100 rows per table page), `MAX_JOB_LOG_LINES` (1000 lines kept per dump / restore log), `DEFAULT_SIDEBAR_WIDTH` (32), `MIN_SIDEBAR_WIDTH` (20), `MAX_SIDEBAR_WIDTH` (80), `SIDEBAR_WIDTH_STEP` (4).
- Messages: `Msg`, `Connection`, `SaveFailure`, `ProfilesMsg`, `TabsMsg`, `SidebarMsg`, `GridMove`, `TableMsg`, `QueryMsg`, `FilesMsg`, `DumpMsg`, `RestoreMsg`, `ModalMsg`.
- Commands: `Command` (connect, catalog / page / details loading, scripts tagged with the tab that runs them and cancellation, saving a table tab's cell edits, SQL files, dumps, restores, clipboard).

## Behaviour highlights

- Every main view is a tab of the workspace. Table tabs opened from the sidebar or the palette are reused per relation (foreign-key navigation reuses them per relation and filter), query tabs are numbered `Query N`, the SQL files, dump and restore tabs are singletons. Ids come from `next_tab_id`; closing the last tab returns focus to the sidebar. Table, query, files, dump and restore messages act on the active tab when it has the matching kind; `PageLoaded` and `DetailsLoaded` reach background tabs too.
- One script runs at a time (`running_script_tab_id`); its `ScriptFinished` is routed to the tab that started it, even after switching tabs, and that tab cannot be closed until it finishes. A pending save remembers its tab, so the saved name lands on the right document.
- The command palette (`Modal::Palette`) lists open tabs, actions (`Toggle sidebar`, `Switch profile…` with the connected label as detail, `Quit` last), then the relations of every schema (current schema first). A non-empty query keeps labels containing its characters as a case-insensitive subsequence, ranked prefix (of the label or of the part after the last `.`), then substring, then subsequence; a query starting with `:` keeps only items whose `command_alias` starts with it (`:q` → `Quit`). Submitting performs the same transition as the matching message; opening a relation of another schema switches the sidebar to it.
- Sidebar size: `SidebarMsg::ToggleCollapsed` collapses the sidebar and focuses the main pane, or expands it and focuses it; `Widen` / `Narrow` change `width` by `SIDEBAR_WIDTH_STEP` within `MIN_SIDEBAR_WIDTH`..=`MAX_SIDEBAR_WIDTH` (on a collapsed sidebar they only expand it); `SetWidth(width)` clamps and expands. A collapsed sidebar is never focused: every focus change to `Focus::Sidebar` (`ToggleFocus`, `FocusPane(Left)`, closing the last tab, `SidebarMsg::Select`) expands it.
- Pointer selection (sent by mouse clicks): `SidebarMsg::Select(index)` selects a sidebar item (clamped) and focuses the sidebar; `TableMsg::SelectCell(cursor)` / `QueryMsg::SelectCell(cursor)` focus the table data / the results pane and move the cursor there, clamped to the page or the selected result; `FilesMsg::Select(index)` selects a SQL file and loads its preview when the selection changed; `RestoreMsg::Select(index)` selects a dump; `ProfilesMsg::Select(profile_index)` selects a visible profile; `ModalMsg::Select(index)` selects a row of the palette, schema picker, reference picker, row detail, enum choice or profile switch popup (`ModalMsg::Next` / `Previous` also step the profile switch popup).

- Connecting replaces the profile picker with a `Workspace` without tabs; reconnecting the same profile keeps the workspace and reloads the catalog and every table tab's page. Switching profile (`Msg::OpenProfilePicker` opens `Modal::ProfilePicker` on the connected profile; `ProfilesMsg::Connect` or `ModalMsg::Submit` there closes it and switches, picking the connected profile only closes it) is refused while a script, a dump or a restore runs, sets `switching_profile_index` and emits `Connect`; its `Connected` swaps profile, session and tools and reloads the catalog and table tabs while query tabs keep their text and results, a failure only shows `Could not connect to <name>: <error>` (names come from `Profile::display_name()`), and a `Connected` for any other profile is ignored. `Run` records the profile label in `QueryView::ran_on_profile_label`. A catalog reload closes table tabs whose relation disappeared.
- Profile picker (start screen `Screen::Profiles` and switch modal `Modal::ProfilePicker`, both driven by `ProfilesMsg`; the modal takes them when open): `profile_rows` groups profiles by project in order of first appearance, then profiles without a project under an `Other` header shown only when some profile has a project. The filter keeps profiles where every whitespace-separated term is a case-insensitive substring of `project label type tags target`; projects without a match disappear. The selection always sits on a visible profile: a filter edit keeps it when still visible, else moves to the first match; `Next` / `Previous` / `First` / `Last` skip headers and clamp; with no match nothing connects. `FocusFilter` / `FocusList` set the mode; on the start screen every message is ignored while connecting.
- Refreshing a ready catalog keeps it visible; after a reload the schema falls back to the current one, then `public`, then the first schema.
- Table pages: pagination, a three-step sort cycle (ascending, descending, none), tables with an `id` column open sorted on `id` descending, a raw `WHERE` filter, row detail, cell copy and draft cell edits.
- Draft cell edits (data tab): `TableView::cell_drafts` (`BTreeMap<GridCursor, Cell>`) keeps changed cells until saved or discarded. `TableMsg::ChangeCell` reads the catalog column of the cursor cell and targets the selected rows (or the cursor row) of that column: enum labels open `Modal::CellEditor` with `CellInput::Choice` (labels in order, a trailing `NULL` when nullable, current value preselected), `boolean` toggles at once (`t` → `f` → `t`, nullable columns `t` → `f` → NULL → `t`), anything else opens `CellInput::Text` with the current value; text wrapped in backticks is saved as a raw SQL expression and `` `NULL` `` (any case) drafts NULL. `TableMsg::SetCellNull` (key `x`) drafts NULL on the same target rows, refused with `<column> is NOT NULL` on non-nullable columns. Views (`Views are read-only`), geometry / geography columns (`Geometry columns cannot be edited inline`), rows without a key or with a NULL key (same rule and messages as the `e` preset) are refused. A value equal to the original page cell removes the draft (an empty text over NULL counts as unchanged); committing clears the selection. `RevertCell` drops the cursor draft, `DiscardDrafts` drops all (`Discarded N change(s)`). While drafts exist, pagination, sort, filter, reload and closing the tab are refused (`Save (Ctrl+s) or discard (U) the N unsaved change(s) first`) and `PageLoaded` leaves the tab alone; reconnecting or switching profile reloads the page and drops them. `SaveDrafts` builds one `UPDATE "schema"."table" SET … WHERE <key> = <original key values>;` per drafted row (rows then columns ascending); `local` emits `Command::SaveCellEdits` at once, `staging` / `prod` ask first with `ConfirmKind::SaveCellEdits` (`Save N change(s) in M row(s) on PROD · <label> (<target>)?`, cancel → `Save cancelled`). `Msg::CellEditsSaved` with one count per statement notices `Saved N row(s)` (Success) or `Saved: X row(s) updated for N edited row(s)` (Warning), clears the drafts and reloads the page; an error notices `Save failed: <message>` and keeps them. `NoticeLevel::Warning` marks refusals that are not errors.
- Foreign keys (data tab, page ready): `TableMsg::GoToReferenced` follows the catalog link of the active relation containing the cursor column (first by constraint name) and opens the referenced relation in a new table tab filtered with `"<referenced column>" = '<value>'` joined with ` AND ` (every column of a composite key, values from the cursor row, through `ducky_sql::quote_identifier` / `quote_literal`). `TableMsg::FindReferencing` lists `Catalog::referencing` for the active relation: none → `No table references <schema>.<name>`, one → opens it filtered on the link's columns with the cursor row's referenced values, several → `Modal::ReferencePicker { links, selected_link_index }` (`Next` / `Previous` / `Submit` / `Cancel`). A non-foreign-key column notifies `<column> is not a foreign key`, a NULL key `<column> is NULL, nothing to follow`. A table tab with the same relation and exactly that filter is activated instead of opening another one; a relation in another schema switches the sidebar to it.
- Row selection (data tab, current page): `TableView::selected_row_indexes()` is `marked_row_indexes` ∪ the range between `visual_anchor_row_index` and the cursor row; `has_selection()` is true when marks or an anchor exist. `TableMsg::ToggleRowMark` toggles the cursor row and moves the cursor down, `ToggleVisualSelection` sets the anchor or folds the range into the marks, `ClearSelection` drops both; reloading a page (pagination, sort, filter, reload) and `PageLoaded` clear it. `TableMsg::EditSelectedRows` targets the selected rows (or the cursor row) by the catalog primary key, else an `id` column (none → `No primary key or id column to target the rows`; a NULL key → `Row <n> has a NULL key, cannot target it`), and opens a new query tab (revision 1, focus main, pane editor) with `UPDATE "<schema>"."<name>"\nSET\n  "<cursor column>" = :<column>\nWHERE <key> IN (<values>)\n;` (`:value` when the column is not a bare identifier, tuples for a composite key), clears the selection and notifies `UPDATE preset for <n> row(s): fill :<param> and press F5`.
- Scripts run in `Transaction` (default) or `AutoCommit` mode; a finished script selects its last result and reloads the catalog when a statement affected rows.
- Run confirmation by the connected profile's kind, applied after the guards and the parameter form, to `Run` and to SQL file execution alike: `local` runs at once; `staging` opens `Modal::Confirm` with `ConfirmKind::RunScript { tab_id, sql }` (the bound SQL) on a tab's first run, and once confirmed (`confirmed_profile_index = Some(profile_index)`) later runs of that tab run directly; switching profile forgets every tab's confirmation, so coming back asks again; `prod` asks before every run. The message reads `Run <n> statement(s) on STAGING|PROD · <label> (<target>)?`. `Submit` re-checks the running guard then emits `RunScript`; `Cancel` runs nothing and notices `Run cancelled`. `FilesMsg::Execute` emits `OpenFile { run_after_open: true }` without a confirmation of its own.
- `Run` of a script containing `:name` or `$n` parameters (also when executing a SQL file) opens `Modal::Parameters` prefilled from the tab's `parameter_values`; `ToggleRaw` switches a field between a string literal and raw SQL, `Submit` stores the values on the tab and runs the bound SQL (guards re-checked), `Cancel` runs nothing.
- Saving an unnamed document prompts for a name and asks before overwriting an existing file.
- Dump and restore are refused with the tool's `Missing` reason when `pg_dump` / `pg_restore` are absent; a restore always asks for confirmation.

cargo test -p ducky-app
